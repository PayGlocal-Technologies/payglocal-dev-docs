<Note>
  These APIs are for **Partners** managing Merchant Collection Accounts. You can only query merchants and transactions that belong to your partner account.
</Note>

## Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| [Fetch Virtual Accounts](/api-reference/mca/account-fetch) | `GET` | Retrieve the global virtual accounts assigned to a merchant, keyed by currency |
| [Upload Document via Presigned URL](/api-reference/mca/document-upload) | `POST` | Attach the supporting invoice to a transaction waiting for a document |
| [MCA Demo Funding Ingestion](/api-reference/mca/mca-ingestion) | `POST` | Sandbox only: simulate an inbound funding event |

---

## Authentication

Every MCA request carries your API key in the `x-gl-auth` header. Which other headers you need depends on the endpoint:

| Endpoint | Headers |
|----------|---------|
| Fetch Virtual Accounts | `x-gl-auth` and `x-gl-digest` |
| Upload Document via Presigned URL | `x-gl-auth` only |
| MCA Demo Funding Ingestion | `x-gl-auth` only |

Fetch Virtual Accounts is the only MCA endpoint that needs a digest. It is `base64(HMAC_SHA256(secret, path))`, where `path` is the request path only, with no host (add `?query` if the request has one). For example, the Fetch Virtual Accounts digest is computed over `/gcc/v3/merchants/<merchantID>/ffms/virtualAccounts`. See [Authentication](/authentication) for the algorithm and code samples.

|----------|------------|---------|
| Fetch Virtual Accounts | `https://api.onboard.payglocal.in` | `https://api.onboard.uat.payglocal.in` |

Each endpoint page shows its own server list. See [Troubleshooting](/mca/troubleshooting) if a call is blocked or returns an unexpected status.

## Response Conventions

- Success responses use a standard envelope with `gid`, `status`, `message`, `timestamp`, `reasonCode`, `data` and `errors`.
- Success responses may carry `"status": "201 CREATED"` with HTTP `200`. Rely on the HTTP status code.
- Quote the response `gid` whenever you contact support.
