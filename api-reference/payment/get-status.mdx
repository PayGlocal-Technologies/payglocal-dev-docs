Query the current state of a transaction after payment initiation. Use this to verify callback data, confirm refund acceptance, or retrieve Standing Instruction IDs.

The Status API is a **GET** request. There is no JSON request body and **no JWE**. Replace `<TXN-GID>` with the `gid` from your initiation response (or your `merchantUniqueId` where supported), then sign the request path with your private key to create the JWS token.

---

## Token Generation

<Warning>
  **Do not send a JSON body on this endpoint.** Build the status path string (`statusPayload="/gl/v1/payments/<TXN-GID>/status"`), sign it with the PayGlocal SDK, and pass only the JWS token in `x-gl-token-external`. JWE is not used for GET Status.
</Warning>

Use the SDK to generate the JWS token from the status path:

```javascript
const { jwsToken } = generateJWS(
  statusPayload="/gl/v1/payments/<TXN-GID>/status",
  pvtKey,       // Your private key (from GCC)
  merchantId,
  pvtKeyId
);
```

| Token | What it is | Where it goes |
|---|---|---|
| `jwsToken` | RSA signature over the status path (`/gl/v1/payments/<TXN-GID>/status`) using your private key | **`x-gl-token-external` header** |

**Generated cURL request:**

```bash
curl -X GET https://api.uat.payglocal.in/gl/v1/payments/<TXN-GID>/status \
  -H "x-gl-token-external: <your-jws-token>"
```

## Path Parameter

| Parameter | Description |
|---|---|
| `{id}` | Transaction GID from initiation response (e.g., `gl-13bbd3c4...`). |

## Transaction Status Values

| Status | Final | Meaning | Action |
|---|---|---|---|
| `CREATED` | No | Registered; awaiting redirect | Redirect to `redirectUrl` |
| `INPROGRESS` | No | Customer on payment page | Wait for completion |
| `AUTHORIZED` | No | Funds held; awaiting capture | Capture or reverse |
| `SENT_FOR_CAPTURE` | Yes | Captured; settlement in progress | Fulfill order |
| `ABANDONED` | Yes | Customer closed payment window | Retry payment |
| `ISSUER_DECLINE` | Yes | Card declined by bank | Try different card |
| `CUSTOMER_CANCELLED` | Yes | Customer cancelled | Retry payment |
| `AUTHENTICATION_TIMEOUT` | Yes | 3DS timed out | Retry payment |
| `GENERAL_DECLINE` | Yes | Declined by risk engine | Contact support |
| `REQUEST_ERROR` | Yes | Invalid request data | Fix and retry |
| `SYSTEM_ERROR` | Yes | PayGlocal system issue | Retry after delay |
| `CONFIG_ERROR` | Yes | MID misconfiguration | Contact support |
| `CONDITIONAL_DECLINE` | Yes | Processing error/timeout | Retry after delay |

### Refund Statuses

| Status | Meaning |
|---|---|
| `SENT_FOR_REFUND` | Refund accepted and sent to processor |
| `REQUEST_ERROR` | Invalid refund request |
| `SYSTEM_ERROR` | System error; retry after delay |
