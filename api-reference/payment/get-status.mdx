## When to Use

Call this endpoint whenever you need the current state of a transaction:

- After receiving a callback — independently verify the status before processing
- When the `merchantCallbackURL` callback was missed, delayed, or failed
- To confirm a refund was accepted
- To retrieve the `maskedMandateId` / `siId` after a successful SI setup

<Note>
  Use Get Status only when the original GPI call returned `CREATED`. If GPI itself returned a terminal error (e.g., `REQUEST_ERROR`, `CONFIG_ERROR`), those are final — Get Status will not change them.
</Note>

---

<Info>
  **Endpoint:** `/gl/v1/payments/{id}/status`

  **Method:** `GET`
</Info>

## How to Call This Endpoint

Get Status is a **GET** request with no body. Authentication still requires a **JWS-signed header**, generated using your credentials via the SDK.

```javascript
const { jwsToken } = generateJWEAndJWS(
  {},           // empty payload for GET requests
  pubCert,
  pvtKey,
  merchantId,
  pubKeyId,
  pvtKeyId
);

// Send: GET /gl/v1/payments/{id}/status
// Header: x-gl-token-external: jwsToken
// No request body
```

The `{id}` path parameter accepts either:
- The PayGlocal `gid` (e.g., `gl-13bbd3c4-9817-4786-96c6-12fa6191f118`)
- Your `merchantUniqueId` from the original GPI request

</Note>

## Transaction Status Values

### GPI Payment Statuses

| Status | Final? | Meaning | Your next action |
|--------|--------|---------|-----------------|
| `CREATED` | No | Transaction registered; customer has not yet redirected | Redirect customer to `redirectUrl` |
| `INPROGRESS` | No | Customer is on PayGlocal's payment page | Wait for customer to proceed |
| `AUTHORIZED` | No | Authorized by issuer; awaiting capture | Plan to ship goods |
| `SENT_FOR_CAPTURE` | **Yes** | Payment captured; settlement in progress | Ship goods; optionally issue refund later |
| `ABANDONED` | **Yes** | Customer closed or timed out the payment window | Send a payment link to retry |
| `ISSUER_DECLINE` | **Yes** | Card declined by the issuing bank | Ask customer to use another card |
| `CUSTOMER_CANCELLED` | **Yes** | Customer cancelled on PayGlocal's page | Ask customer to retry |
| `AUTHENTICATION_TIMEOUT` | **Yes** | 3DS authentication timed out | Ask customer to retry |
| `GENERAL_DECLINE` | **Yes** | Declined by PayGlocal's risk engine | Check customer profile |
| `REQUEST_ERROR` | **Yes** | Field-level error in the original request | Fix the payload and retry |
| `SYSTEM_ERROR` | **Yes** | PayGlocal system issue | Retry after some time |
| `CONFIG_ERROR` | **Yes** | MID misconfiguration | Contact PayGlocal merchant support |
| `CONDITIONAL_DECLINE` | **Yes** | Processing error or timeout | Retry after some time |

### Refund Statuses

| Status | Final? | Meaning |
|--------|--------|---------|
| `SENT_FOR_REFUND` | **Yes** | Refund accepted and sent to processor |
| `REQUEST_ERROR` | **Yes** | Fix request fields and retry |
| `SYSTEM_ERROR` | **Yes** | Retry after some time |

## Response Fields

| Field | Description |
|---|---|
| `gid` | PayGlocal transaction ID |
| `status` | Current transaction status |
| `reasonCode` | PayGlocal reason code |
| `data.Amount` | Transaction amount |
| `data.Currency` | Transaction currency |
| `data.merchantTxnId` | Your original transaction reference ID |
| `data.siStatus` | SI setup result (`SUCCESS` / `FAILURE`) — SI transactions only |
| `data.maskedMandateId` | Masked mandate ID for subsequent SI payments — SI transactions only |
| `data.siId` | Standing Instruction ID for GCC management — SI transactions only |
