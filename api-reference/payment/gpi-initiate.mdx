## When to Use

Use **PayDirect** when your integration is **PCI DSS certified** and you collect the customer's full card details (card number, expiry, CVV) on your own checkout page.

<Warning>
  **PCI DSS compliance is mandatory** for this flow. You are responsible for securely collecting, transmitting, and handling cardholder data. If you are not PCI certified, use [PayCollect](/api-reference/payment/gpi-paycollect) instead.
</Warning>

---

<Info>
  **Endpoint:** `/gl/v1/payments/initiate`

  **Method:** `POST`
</Info>

## Step 2 — Encrypt, Sign, and Send

<Warning>
  **You cannot send raw JSON to PayGlocal payment endpoints.** Every request body must be JWE-encrypted and the header must carry a JWS-signed token. Both are generated from your credentials using PayGlocal's client SDK.
</Warning>

Pass the raw payload above to `generateJWEAndJWS()` from PayGlocal's client SDK:

```javascript
const { jweToken, jwsToken } = generateJWEAndJWS(
  rawPayload,   // the JSON object you built in Step 1
  pubCert,      // PayGlocal's PUBCERT — encrypts payload → JWE body
  pvtKey,       // Your PVT-KEY — signs JWE → JWS header
  merchantId,
  pubKeyId,
  pvtKeyId
);

// jweToken → send as the request body (text/plain)
// jwsToken → send as the x-gl-token-external header
```

The resulting HTTP call has the form:

```
POST /gl/v1/payments/initiate
Content-Type: text/plain
x-gl-token-external: [jwsToken from SDK]

[jweToken from SDK]
```

<Note>
  See [Payment Flow](/merchant/payment-flow) for the full JWE + JWS transformation, and [Key Management](/getting-started/dashboard-and-key-management) for credentials setup.
</Note>

## Response

### Success (`HTTP 200`)

```json
{
  "gid": "gl-13bbd3c4-9817-4786-96c6-12fa6191f118",
  "status": "CREATED",
  "message": "Transaction Created Successfully",
  "timestamp": "2021-04-12T07:47:18Z",
  "reasonCode": "GL-201-001",
  "data": {
    "redirectUrl": "https://api.uat.payglocal.in/gl/v1/payments/redirect?x-gl-token=eyJ...",
    "statusUrl": "https://api.uat.payglocal.in/gl/v1/payments/status?x-gl-token=eyJ..."
  },
  "errors": null
}
```

### Response Fields

| Field | Description |
|---|---|
| `gid` | PayGlocal's unique transaction ID. Save this — all follow-on calls use it. |
| `status` | `CREATED` on success. This is not a final payment status. |
| `data.redirectUrl` | Redirect the customer's browser here via HTTP **GET** to complete 3DS / payment. |
| `data.statusUrl` | Convenience URL for a Get Status call on this transaction. |
| `data.mandateId` | Present only when `standingInstruction` was included. Confirm via Get Status after payment. |

---

## What to Do After a `CREATED` Response

```
1. Save the gid from the response
2. Redirect the customer's browser to data.redirectUrl using HTTP GET
   ⚠️  Never use HTTP POST for the redirect
3. Customer completes 3DS on PayGlocal's page
4. PayGlocal POSTs the result to your merchantCallbackURL as x-gl-token
5. Decode the callback JWT and act on the payment status
```

If the callback is delayed or missed, poll [Get Status](/api-reference/payment/get-status) using the `gid`.

---

## Notes

- `merchantUniqueId` must be globally unique per MID. Do not prefix it with `gl-`.
- `merchantCallbackURL` must be a publicly accessible HTTPS POST endpoint.
- `ipAddress`, `httpAccept`, and `httpUserAgent` in `riskData.customerData` are mandatory for **RuPay card** transactions.
- For **international card** transactions, `riskData` is required — missing risk data may cause rejection.
- For **Portfolio (Parent-Child MID)** setups: pass `x-gl-kid-mid: <parent-MID>` as an additional request header and set the child MID as the `merchantId`.

## Error Scenarios

| HTTP code | Reason code | Description | Action |
|---|---|---|---|
| `400` | `GL-400-002` | Invalid data in request | Check field values and types |
| `400` | `GL-400-003` | Missing `merchantTxnId` | Add the required field |
| `400` | `GL-400-004` | Card type not enabled for this MID | Contact PayGlocal support |
| `400` | `GL-400-007` | Card type is not valid | Verify card number and type |
| `201` | `GL-201-020` | MID misconfigured | Contact PayGlocal support |
| `501` | `GL-501-000` | System error | Retry after some time |
