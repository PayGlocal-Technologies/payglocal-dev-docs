All Payment API requests (PayCollect and PayDirect, GPI, SI, Auth & Capture) use the same authentication scheme: RSA JWS signing.

## When to Use

Use this authentication scheme for every request you send to PayGlocal Payment APIs (PayCollect, PayDirect, GPI, Standing Instructions, and Auth & Capture). There is no alternative — all environments (sandbox and production) require RSA JWS-signed headers. Obtain your RSA key pair and key ID (`x-gl-kid`) from the PayGlocal merchant portal before making your first API call. If you are on a parent-child (Portfolio) MID setup, also read the Portfolio / Multi-MID section below.

## Signing Flow

<Steps>
  <Step title="Serialize the request body">Convert your request payload to a JSON string.</Step>
  <Step title="Sign with your private key">Generate a JWS token by signing the serialized body with your RSA private key using RS256.</Step>
  <Step title="Set headers and POST">Include `x-gl-token-external` (JWS token), `x-gl-merchantid`, `x-gl-kid`, and `Content-Type: application/json`.</Step>
</Steps>

For code samples, see [Request Construction](/set-up/keys/request-construction).

## PayDirect: Additional JWE Encryption

For PayDirect flows that include card data, the card data sub-object must be JWE-encrypted with PayGlocal's public certificate (PUBCERT) before JWS signing.

<Warning>
Do not send raw card data without JWE encryption in PayDirect flows. This is a PCI DSS violation.
</Warning>

See [Request Signing and Encryption](/payments/lifecycle/request-signing) for JWE + JWS code samples.

## Portfolio / Multi-MID

For parent-child MID configurations, add the `x-gl-kid-mid` header with the child MID. The `x-gl-kid` remains the parent's KID.

## Example

<CodeGroup>

```json Request (headers)
{
  "x-gl-merchantid": "<MERCHANT_ID>",
  "x-gl-kid": "<KID>",
  "x-gl-token-external": "<JWS_TOKEN>",
  "Content-Type": "application/json"
}
```

```json Response (200)
{
  "status": "SUCCESS",
  "message": "Request authenticated successfully."
}
```

</CodeGroup>

## Error Scenarios

| Scenario | HTTP Code |
|---|---|
| Missing or malformed `x-gl-token-external` header | 401 |
| JWS signature verification failed (wrong private key or tampered payload) | 401 |
| `x-gl-merchantid` does not match the signing key | 403 |
| Unknown or expired `x-gl-kid` | 403 |
| Request body does not match the signed payload | 400 |
