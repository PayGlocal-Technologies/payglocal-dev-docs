## AUTO DEBIT standing instructions

**AUTO DEBIT** standing instructions automatically process subsequent debits based on the configured schedule after successful mandate registration.

Registration uses the same PayCollect initiate endpoint as [GPI](/api-reference/payments-v2/paycollect/gpi) with a `standingInstruction` block. The customer completes mandate setup on the **hosted checkout** page.

### Key points

- Register the mandate using the **Initiate API** with **`startDate`** and a scheduled **`frequency`** such as `WEEKLY`, `BIWEEKLY`, `MONTHLY`, `QUARTERLY`, `HALFYEARLY`, or `YEARLY` (not `ONDEMAND`).
- After successful registration, subsequent debit transactions are **automatically initiated** according to the configured schedule.
- **No [SI sale API](/api-reference/standing-instructions/si-subsequent-payment) calls** are required for subsequent debit transactions.
- The amount for subsequent debits must be **`FIXED`**.

<Warning>
  When **Auto Debit** is enabled for your MID, `ONDEMAND` frequency and `VARIABLE` type are not supported.
</Warning>

<Note>Store the mandateId from the initial mandate-registration payment — it is required for all auto-debit charges.</Note>

---

## When to Use

Use this endpoint when you need to register a **scheduled, fixed-amount recurring mandate** and want PayGlocal to automatically trigger each subsequent debit without any further API calls from your side. This is the right flow when:

- The debit amount is fixed and the schedule is known upfront (e.g. monthly subscription, quarterly fee).
- You want the customer to register the mandate on the **PayGlocal hosted checkout** — no card data is handled on your servers.
- The customer is paying with an **international card**; UPI, net banking, and domestic-only methods are not supported for SI registration on hosted checkout.
- You do **not** want to call the [SI subsequent payment API](/api-reference/standing-instructions/si-subsequent-payment) for each recurring charge — use [on-demand SI](/api-reference/payments-v2/paycollect/si-on-demand) instead if you need to control each debit individually.

## Supported payment methods

| Method | Domestic | International |
|--------|:--------:|:-------------:|
| Cards | — | ✓ |

Standing instruction registration on hosted checkout supports **international cards** only. UPI, net banking, and domestic-only methods are not supported for SI.

## Notes

- Do **not** send **`cardData`** or **`tokenData`** — the customer registers the mandate on the PayGlocal hosted page.

## Error Scenarios

| Scenario | HTTP Code |
|----------|-----------|
| Missing or invalid `standingInstruction.data` fields (e.g. `amount`, `frequency`, `startDate`) | 400 |
| `frequency` set to `ONDEMAND` when auto debit is enabled on the MID | 400 |
| `type` set to `VARIABLE` when auto debit is enabled on the MID | 400 |
| Missing required `paymentData` fields (`totalAmount`, `txnCurrency`) | 400 |
| Invalid or expired `x-gl-token-external` JWS token | 401 |
| `merchantTxnId` already used for a previous transaction | 400 |
