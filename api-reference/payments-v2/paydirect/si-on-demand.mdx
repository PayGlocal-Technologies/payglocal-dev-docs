## On-demand standing instructions

**On-demand SI** is a **PayGlocal MID configuration** — not a restriction that `standingInstruction.data.frequency` must be `ONDEMAND`. You can set any supported `frequency` in the request body.

Use this flow when on-demand SI is enabled for your account. Registration uses the same PayDirect initiate endpoint as [GPI](/api-reference/payments-v2/paydirect/gpi) with a `standingInstruction` block.

### Key points

- Register the mandate using the **Initiate API** with `standingInstruction.data` (see **Request body**).
- **`frequency`** (`ONDEMAND`, `WEEKLY`, `MONTHLY`, etc.) is a mandate field only — PayGlocal does **not** auto-debit on that schedule for on-demand SI. You trigger **every** subsequent debit by calling the **[SI sale API](/api-reference/standing-instructions/si-subsequent-payment)** (billing cadence is up to you).
- Subsequent debit amounts:
  - **`FIXED`** — same `amount` each time.
  - **`VARIABLE`** — up to `maxAmount` per debit.
- **`mandateId`** is returned in the Initiate API response (`data.mandateId`) and must be stored for future mandate operations. It is **not returned again** in later transactions.

---

## When to Use

Use this endpoint when PayGlocal has enabled **on-demand SI** on your merchant ID and you want to register a card mandate at the point of sale. Call this instead of the standard [GPI initiate](/api-reference/payments-v2/paydirect/gpi) whenever you need to capture card details and create a reusable mandate in a single step.

Do not use this endpoint if your MID is configured for [auto-debit SI](/api-reference/payments-v2/paydirect/si-auto-debit) — that flow requires `startDate`/`endDate` fields and PayGlocal handles the debit schedule automatically. This endpoint is also not suitable for domestic-only cards, UPI, or net banking; only international cards are supported.

---

## Supported payment methods

| Method | Domestic | International |
|--------|:--------:|:-------------:|
| Cards | — | ✓ |

Standing instructions support **international cards** only. In **Request body** → `paymentData`, send **`cardData` only** (`tokenData` is not supported). UPI, net banking, and domestic-only methods are not supported.

## Error Scenarios

| Scenario | HTTP Code |
|----------|-----------|
| Invalid request fields or error processing request (`GL-400-001`) | 400 |
| Card domicile or card type not set up in merchant config; merchant configuration mismatch (`GL-201-020`) | 400 |
| Merchant is blacklisted and not permitted to transact (`GL-403-001`) | 403 |
| Too many requests with the same `merchantUniqueId` (`GL-400-001`) | 429 |
