Create a **Standing Instruction (SI) mandate** together with the customer’s first payment. Use **PayCollect** (`POST /gl/v1/payments/initiate/paycollect`) and include a `standingInstruction` object in the same payload you encrypt and sign for a regular PayCollect payment.

After a successful setup, save the **mandate ID** from the response (or from [Get Status](/api-reference/payment/get-status)) for [subsequent charges](/api-reference/standing-instructions/si-subsequent-payment), [mandate status](/api-reference/standing-instructions/si-status), and [pause / activate / cancel](/api-reference/standing-instructions/si-cancellation).

<CardGroup cols={2}>
  <Card title="Fixed — Auto Debit" icon="calendar" color="#10B981">
    Same amount debited automatically on a schedule. PayGlocal runs each cycle — no per-cycle API call.
  </Card>
  <Card title="Variable — On-Demand" icon="hand-pointer" color="#F59E0B">
    You trigger each charge with [SI Subsequent Payment](/api-reference/standing-instructions/si-subsequent-payment). Amount can vary up to `maxAmount`.
  </Card>

## Raw Payload

Build one of the JSON payloads below. This is **human-readable** business data — it is **never sent directly**. Encrypt and sign it before transmission (same flow as [Pay Collect](/api-reference/payment/gpi-paycollect)).

### Fixed SI (Auto Debit)

Creates a mandate with a fixed recurring amount auto-debited on a schedule.

```json
{
  "merchantUniqueId": "IFNN939494NJFJ",
  "merchantTxnId": "23AEE8CB6B62EE2AF07",
  "paymentData": {
    "totalAmount": "89",
    "txnCurrency": "USD"
  },
  "standingInstruction": {
    "data": {
      "amount": "89",
      "numberOfPayments": "12",
      "frequency": "MONTHLY",
      "type": "FIXED",
      "startDate": "20260601"
    }
  },
  "merchantCallbackURL": "https://www.yoursite.com/callback"
}
```

### Variable SI (On-Demand)

Creates a mandate where you trigger each charge manually with a variable amount (up to `maxAmount`).

```json
{
  "merchantUniqueId": "IFNN939494NJFJ",
  "merchantTxnId": "23AEE8CB6B62EE2AF07",
  "paymentData": {
    "totalAmount": "500.00",
    "txnCurrency": "INR"
  },
  "standingInstruction": {
    "data": {
      "type": "VARIABLE",
      "frequency": "ONDEMAND",
      "numberOfPayments": "999",
      "maxAmount": "5000.00"
    }
  },
  "merchantCallbackURL": "https://yourwebsite.com/callback"
}
```

## Token Generation

<Warning>
  **The raw payload above cannot be sent directly.** It must be encrypted into a JWE token and signed into a JWS token using the PayGlocal SDK before any API call.
</Warning>

Use the SDK to generate both tokens from your raw payload:

```javascript
const { jweToken, jwsToken } = generateJWEAndJWS(
  rawPayload,   // JSON payload built above
  pubCert,      // PayGlocal's public certificate (from GCC)
  pvtKey,       // Your private key (from GCC)
  merchantId,
  pubKeyId,
  pvtKeyId
);
```

| Token | What it is | Where it goes |
|---|---|---|
| `jweToken` | Your payload, AES-256 encrypted with PayGlocal's public cert | **Request body** (`text/plain`) |
| `jwsToken` | RSA signature over the JWE token using your private key | **`x-gl-token-external` header** |

**Generated cURL request:**

```bash
curl -X POST https://api.uat.payglocal.in/gl/v1/payments/initiate/paycollect \
  -H "Content-Type: text/plain" \
  -H "x-gl-token-external: <your-jws-token>" \
  -d "<your-jwe-token>"
```

## Request Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `merchantUniqueId` | string | Yes | Your unique order/transaction ID. Must not start with `gl-`. |
| `merchantTxnId` | string | Yes | Internal transaction reference. |
| `paymentData.totalAmount` | string | Yes | First payment amount (and fixed debit amount for **Fixed** SI). |
| `paymentData.txnCurrency` | string | Yes | ISO 4217 currency code. |
| `standingInstruction.data` | object | Yes | Mandate configuration — see tables below. |
| `merchantCallbackURL` | string | Yes | HTTPS POST endpoint for payment and mandate setup results. |

### `standingInstruction.data` — Fixed (`type: "FIXED"`)

| Field | Required | Description |
|---|---|---|
| `amount` | Yes | Amount debited each cycle (e.g., `"89"`). |
| `numberOfPayments` | Yes | Total number of cycles (e.g., `"12"`). |
| `frequency` | Yes | `DAILY`, `WEEKLY`, `MONTHLY`, `QUARTERLY`, `YEARLY`. |
| `type` | Yes | Must be `"FIXED"`. |
| `startDate` | Yes | Schedule start date in `YYYYMMDD` format. |

### `standingInstruction.data` — Variable (`type: "VARIABLE"`)

| Field | Required | Description |
|---|---|---|
| `type` | Yes | Must be `"VARIABLE"`. |
| `frequency` | Yes | Must be `"ONDEMAND"`. |
| `numberOfPayments` | Yes | Maximum number of on-demand debits allowed. |
| `maxAmount` | Yes | Maximum amount per on-demand charge. |

<Note>
  More payload variants are in [Payload Templates](/api-reference/payload-templates) under **Standing Instruction (SI) Payloads**.
</Note>

## Response

### Success

```json
{
  "gid": "gl-7f8e2a4c-1234-5678-90ab-cdef12345678",
  "status": "CREATED",
  "message": "Transaction Created Successfully",
  "timestamp": "2026-05-23T10:15:42Z",
  "reasonCode": "GL-201-001",
  "data": {
    "redirectUrl": "https://api.uat.payglocal.in/gl/v1/payments/redirect?x-gl-token=eyJ...",
    "statusUrl": "https://api.uat.payglocal.in/gl/v1/payments/status?x-gl-token=eyJ..."
  },
  "errors": null
}
```

### After `CREATED`

1. Save the `gid` from the response
2. Redirect the customer to `data.redirectUrl` via **HTTP GET** (never POST)
3. Customer completes payment and mandate registration on PayGlocal’s hosted page
4. PayGlocal POSTs the result to your `merchantCallbackURL`
5. Use [Get Status](/api-reference/payment/get-status) to read `maskedMandateId` / `siId` when SI setup completes

<Warning>
  Store the **mandate ID** securely. Every future SI operation requires it.
</Warning>

## Error Responses

| HTTP | Reason Code | Description | Action |
|---|---|---|---|
| `400` | `GL-400-002` | Invalid request data | Verify `standingInstruction.data` fields |
| `400` | `GL-400-003` | Missing `merchantTxnId` | Include required field |
| `400` | `GL-400-004` | Card type not enabled | Contact PayGlocal support |
| `201` | `GL-201-020` | MID misconfigured | Contact PayGlocal support |
| `501` | `GL-501-000` | System error | Retry after delay |
