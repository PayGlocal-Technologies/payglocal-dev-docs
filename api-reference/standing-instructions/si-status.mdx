## When to Use

- Before triggering a subsequent payment — confirm the mandate is still `ACTIVE`
- After pausing or revoking — confirm the action succeeded
- To check how many payments remain before the mandate is exhausted
- For reconciliation and mandate lifecycle management

---

<Info>
  **Endpoint:** `/gl/v1/payments/si/status`

  **Method:** `POST`
</Info>

## Step 1 — Build Your Raw Business Payload

```json
{
  "merchantTxnId": "STATUS-23AEE8CB6B62EE2AF07",
  "standingInstruction": {
    "mandateId": "md_c87fcf0a-a62c-4dae-b001-ee69fee587c3"
  }
}
```

const { jweToken, jwsToken } = generateJWEAndJWS(

## Mandate Status Values

| Status | Description | Can charge again? |
|---|---|---|
| `ACTIVE` | Mandate is live and accepting debits | Yes |
| `INACTIVE` | Mandate was paused or revoked | No — resume via `ACTIVATE` or create new mandate |
| `EXHAUSTED` | All `numberOfPayments` have been processed | No — create a new mandate |

---

## Response Fields — `mandateData`

| Field | Description |
|---|---|
| `mandateStatus` | Current state: `ACTIVE`, `INACTIVE`, or `EXHAUSTED` |
| `mandateCreateDate` | Date the mandate was created (`yyyyMMdd`) |
| `mandateExhaustionDate` | Date the mandate was exhausted — only present when `EXHAUSTED` |
| `maskedMandateId` | Use this in [SI Sale](/api-reference/standing-instructions/si-subsequent-payment) requests |
| `siId` | Standing Instruction reference for the PayGlocal Control Center |
| `numberOfPaymentsProcessed` | Total successful debits completed |
| `numberOfPaymentsRemaining` | Remaining debits before exhaustion |

---

## Notes

- `merchantTxnId` must be unique per request.
- If `mandateStatus` is `INACTIVE` due to a pause, use [SI Cancel / Pause / Activate](/api-reference/standing-instructions/si-cancellation) with `action: ACTIVATE` to resume.
- If `mandateStatus` is `EXHAUSTED`, create a new mandate via a fresh GPI payment with `standingInstruction` data.
