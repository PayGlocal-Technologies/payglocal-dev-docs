# PayGlocal Developer Documentation — Content Restructuring Plan

> Generated by multi-agent content audit (20 reader agents + 1 synthesis agent).
> Last updated: 2026-06-08. Branch: portal-redesign-v7.

---

## Executive Summary

### The 5 Most Critical Content Problems

**1. Catastrophic duplication of authentication, headers, and environment URLs**
The four required request headers (`Content-Type`, `x-gl-token-external`, `x-gl-merchantid`, `x-gl-kid`), the two environment base URLs, and the JWS/JWS comparison prose each appear verbatim in 6–8 files simultaneously. The headers table alone exists in `paycollect/gpi.mdx`, `paycollect/si-on-demand.mdx`, `paycollect/auth-capture-authorise.mdx`, `paydirect/gpi.mdx`, `paydirect/si-on-demand.mdx`, and `paydirect/auth-capture-authorise.mdx`. Any change to authentication mechanics requires editing 6+ files and risks drift.

**2. Three parallel error-code files with no canonical source**
`reference/error-codes.mdx`, `reference/response-codes-and-errors.mdx`, and `api-fields/response-codes.mdx` all contain overlapping content. The first two share a near-verbatim Onboarding API error section. The second and third both contain the full GL-xxx reason code tables. Developers consulting any one file get an incomplete or potentially stale picture.

**3. Critical security gaps that could cause compliance failures**
`merchant/paydirect/jwt-authentication.mdx` contains realistic-looking card numbers (replace with `<TEST_CARD_NUMBER>` or `4111111111111111`). `api-reference/callback-handling.mdx` teaches JWT decoding without teaching signature verification. `mca/webhooks.mdx` and `guides/webhooks.mdx` document webhook consumption without covering HMAC/signature verification. These are not cosmetic issues — they teach developers to build insecure integrations.

**4. Fundamentally misnamed files that misdirect developers**
`merchant/paycollect/jwt-authentication.mdx` and `merchant/paydirect/jwt-authentication.mdx` are titled "JWT Authentication" but contain payment API quickrefs. `merchant/payment-flow.mdx` and `integration/payment-flow.mdx` share an identical title but describe sequential, non-overlapping concepts (token construction vs. redirect lifecycle). `api-reference/codedrop.mdx` and `merchant/paycollect/codedrop.mdx` are near-identical 880-word duplicates of each other.

**5. Missing foundational concept pages that every integration depends on**
There is no Core Concepts page explaining the partner/merchant/GPI/GID object model. There is no transaction status lifecycle reference table that enumerates all statuses as a single lookup. There is no dedicated Sandbox page listing test cards, UPI VPAs, test credentials, and environment URLs. There is no Idempotency reference. There is no complete x-gl-token callback payload reference. Without these, developers hit undefined terms on every page and must open support tickets to answer questions that documentation should answer.

**Current state:** Three files exist at different directory levels (`introduction.mdx` at root, `quickstart.mdx` at root, `guides/integration-chooser.mdx`). `introduction.mdx` is a marketing card-grid with no developer-oriented content. `quickstart.mdx` is actually a partner merchant onboarding quickstart, not a payment integration quickstart. `integration-chooser.mdx` is the strongest page but uses ASCII art decision trees and has a grammatically awkward title. No Core Concepts page exists. No Sandbox page exists. No Glossary exists.

**Optimal structure:**

- `get-started/overview.mdx` — One-paragraph platform description in developer terms (RBI-licensed payment aggregator, API surface: merchant onboarding + payment initiation + 3DS + settlement + recurring), a labelled architecture diagram showing the partner/merchant/GPI/GID object model, and a numbered reading-order list pointing developers to their first four actions.

This file supersedes the scattered UAT hints across 7+ files.
- `get-started/choose-integration.mdx` — The refactored `integration-chooser.mdx`: Mintlify Steps decision tree (not ASCII art), comparison table with riskData/MID-configuration axes added, links forward to PayCollect and PayDirect. Title changed to "Choose Your Integration Pattern."
- `get-started/glossary.mdx` — Definitions of GPI, GID, GCC, PAN, MID, KID, DCC, Standing Instructions, Mandate ID, VKYC, DigiLocker, PayCollect, PayDirect, CodeDrop, MCA, FIRC, x-gl-auth, x-gl-digest, x-gl-token, JWS, JWE, onboardingId, merchantUniqueId.
