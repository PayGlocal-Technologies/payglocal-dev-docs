## Before You Contact Support

Most MCA issues are one of the following. Check these first.

<AccordionGroup>
  <Accordion title="401 with Authentication failed on Fetch Virtual Accounts">
    **Likely cause:** `x-gl-digest` is missing, or computed over the wrong input

    **What to do:** Send both `x-gl-auth` and `x-gl-digest`, and sign the request path only (no host).
  </Accordion>
  <Accordion title="401 on Upload Document">
    **Likely cause:** `x-gl-auth` is missing or wrong

    **What to do:** Send your API key in `x-gl-auth`. No digest is needed for this endpoint.
  </Accordion>
  <Accordion title="Plain-text 403 mentioning 'geographic constraints'">
    **Likely cause:** The request came from outside India

    **What to do:** Send it from an India-hosted server. See [Blocked requests](#blocked-requests).
  </Accordion>
  <Accordion title="JSON 403">
    **Likely cause:** The `merchantId` or `gid` does not belong to your partner account

    **What to do:** Check you are using the right ID for your own merchants.
  </Accordion>
  <Accordion title="Fetch Virtual Accounts returns 200 but no data">
    **Likely cause:** Accounts are not provisioned yet

    **What to do:** Wait for the `VIRTUAL_ACCOUNT_PROVISIONED` webhook.
  </Accordion>
  <Accordion title="Upload returns 400 not open for new document upload">
    **Likely cause:** The transaction is not in `DOCUMENT_PENDING`

    **What to do:** Check the latest webhook for that `gid`.
  </Accordion>
  <Accordion title="Upload returns 400 Invalid file extension">
    **Likely cause:** `fileName` is not a `.pdf`

    **What to do:** Send a PDF with a `.pdf` file name.
  </Accordion>
  <Accordion title="Uploaded, but nothing happens">
    **Likely cause:** The file failed the 10 MB or PDF check after the `200`, or is waiting for review

    **What to do:** Upload a corrected file. If still stuck, contact support with the `gid`.
  </Accordion>
  <Accordion title="Webhook never arrives">
    **Likely cause:** The event is not enabled for you, or your endpoint is failing

    **What to do:** Confirm the subscription key with your account manager, and check your endpoint returns `2xx` without redirects.
  </Accordion>
</AccordionGroup>

## Blocked Requests

<Warning>
  **Your request was sent from outside India.** PayGlocal accepts these calls only from within India, so a request that originates elsewhere is stopped before it reaches the API. This is not an authentication or signing problem.
</Warning>

You will see a short plain-text reply (not JSON, with no `gid` or `reasonCode`):

> Your access attempt has been noted. Currently, this service is available under specific geographic constraints. If you believe you are receiving this message in error, please contact our support.

The HTTP status is `403`.

**What to check**

- Where is the machine that sends the request? A server, cloud function or CI runner hosted outside India is blocked, even if your team is in India.
- Is the call going out through a VPN, proxy or NAT gateway in another country?

**How to fix it**

1. Send the request from a server hosted in India, or route it through an India-based egress IP.
2. Use the documented host for the endpoint. See [Servers](/api-reference/mca/overview#servers).
3. If the request does come from India and is still blocked, contact support with the **public egress IP**, the **region** and the time of the request.

## Authentication Checklist

- `x-gl-auth` is your API key. Where a digest is required, `x-gl-digest` is `base64(HMAC_SHA256(secret, signingInput))`.
- Fetch Virtual Accounts is the only endpoint that needs a digest. `signingInput` is the request path, for example `/gcc/v3/merchants/<merchantId>/ffms/virtualAccounts`. Add `?query` only if the request has a query string. Do not include the host or scheme.
- Upload Document and Demo Funding Ingestion need only `x-gl-auth`.
- The secret must be the one paired with the API key you send.

See [Authentication](/authentication) for code samples.

## What to Send Support

Include as much of this as you have. It lets us find your request without back-and-forth.

- The `gid` from the response (error responses include one) or from the webhook
- The merchant ID and the environment (sandbox or production)
- The endpoint, HTTP method and status code you received
- The time of the request, with time zone
- For blocked requests: the public egress IP and region
- For webhook issues: the event name, the `gid`, and your endpoint's response to a test POST

Never send your API secret, your full API key, or customer card or bank data.
