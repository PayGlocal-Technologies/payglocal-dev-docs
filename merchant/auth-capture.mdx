## Auth & Capture

A two-step payment process that gives you maximum flexibility. First, you authorize and hold funds on the customer's payment method. Then, you capture the funds when you're ready to complete the transaction. Ideal for businesses that need time between order placement and fulfillment.

<Note>
  Authorization typically holds **7–30 days** depending on the issuer and card network. Actual hold window may vary.
</Note>

Available for both [PayCollect](/merchant/paycollect/overview) and [PayDirect](/merchant/paydirect/overview) integrations.

## The 3-Stage Flow

```
Auth Payment       →     Capture (full or partial)     →     [optional] Auth Reversal
  hold funds              charge customer                       release held funds
(captureTxn: false)
```

**Step 1.** Authorize payment to hold funds (`captureTxn: false`)
**Step 2.** Capture the authorized amount (full or partial)
**Step 3.** Release remaining funds automatically or via reversal

Multiple partial captures are allowed until the full authorized amount is captured. Auth reversal cancels the authorization and releases all held funds. Webhook notifications are sent at each stage.

## Step 1: Auth Payment

Authorize and hold funds on the customer's payment method without immediate capture.

### Endpoint

```
POST /gl/v1/payments/auth
```

### Request

```json
{
  "merchantTxnId": "23AEE8CB6B62EE2AF07",
  "paymentData": {
    "totalAmount": "100.00",
    "txnCurrency": "INR",
    "cardData": {
      "number":       "4242424242424242",
      "expiryMonth":  "05",
      "expiryYear":   "2028",
      "securityCode": "173"
    }
  },
  "captureTxn": false
}
```

### Key Points

- Hold funds without charging the customer immediately
- Requires `captureTxn: false` in the request payload
- Returns Global ID (`gid`) for subsequent capture / reversal operations
- Customer sees the amount as "pending" on their statement
- Use [Status Check](/merchant/services/status-check) to monitor authorization status

### Response

```json
{
  "gid":     "gl-13bbd3c4-9817-4786-96c6-12fa6191f118",
  "status":  "AUTHORIZED",
  "message": "Authorization Successful"
}
```

<Warning>
  **Store the GID** — you'll use it in the Capture or Reversal request.
</Warning>

## When to Use Each Operation

| Scenario | Operation |
|----------|-----------|
| Authorize a payment now, ship later | **Auth Payment** (above) |
| Customer payment approved, ready to ship | [Capture Payment](/merchant/services/capture-payment) (full or partial) |
| Order cancelled before shipping | [Auth Reversal](/merchant/services/auth-reversal) |
| Already captured, customer wants money back | [Initiate Refund](/merchant/services/initiate-refund) |
