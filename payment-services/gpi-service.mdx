## What Is GPI?

**GPI (PayGlocal Payment Initiation)** is the primary API service for initiating a payment transaction. It collects all transaction, payment, and risk data in a single request and returns a redirect URL for your customer to complete the payment.

The GPI service performs:
1. Determining processing attributes and routing for the transaction
2. Validating and processing payment data
3. Risk assessment and transaction classification
4. Setting up standing instructions (if requested)

## Two Integration Flows

### PayCollect Flow — For Non-PCI DSS Certified Entities

You send minimal transaction data (amount, currency, merchant identifiers). PayGlocal collects card details and preferred payment method directly from the customer on its hosted page.

**Endpoint:** `POST /gl/v1/payments/initiate/paycollect`

**Minimum required payload:**
```json
{
  "merchantTxnId": "23AEE8CB6B62EE2AF07",
  "paymentData": {
    "totalAmount": "89",
    "txnCurrency": "INR"
  },
  "merchantCallbackURL": "https://www.yoursite.com/callback"
}
```

<Note>
  PayCollect supports **Global Alternative Payment Methods** (iDeal, Sofort, Trustly, giropay, EPS, bank transfers, wallets, BNPL) for merchants exporting goods/services outside India. For these methods, `shippingData.addressCountry` and `customerData.emailId` are required.
</Note>

<Warning>
  PayCollect flow does **not** support setting up Standing Instructions for cards.
</Warning>

### PayDirect Flow — For PCI DSS Certified Entities

You collect full card details from the customer on your page and send them directly in the GPI request. You must be PCI DSS compliant to use this flow.

**Endpoint:** `POST /gl/v1/payments/initiate`

**Minimum required payload:**
```json
{
  "merchantTxnId": "23AEE8CB6B62EE2AF07",
  "paymentData": {
    "totalAmount": "89",
    "txnCurrency": "INR",
    "cardData": {
      "number": "5132552222223470",
      "expiryMonth": "12",
      "expiryYear": "2030",
      "securityCode": "123"
    }
  },
  "merchantCallbackURL": "https://www.yoursite.com/callback"
}
```

## GPI Response

```json
{
  "gid": "gl-13bbd3c4-9817-4786-96c6-12fa6191f118",
  "status": "CREATED",
  "message": "Transaction Created Successfully",
  "timestamp": "2021-04-12T07:47:18Z",
  "reasonCode": "",
  "data": {
    "redirectUrl": "https://api.prod.payglocal.in/gl/v1/payments/redirect?x-gl-token=...",
    "statusUrl": "https://api.prod.payglocal.in/gl/v1/payments/status?x-gl-token=..."
  },
  "errors": null
}
```

For SI requests, the response also includes:
```json
{
  "data": {
    "redirectUrl": "...",
    "statusUrl": "...",
    "mandateId": "md_94f0bb40-2664-4851-ab83-b86c618d3e15"
  }
}
```

## Risk Data Requirements

<Warning>
  For **international card** transactions, `riskData` is **required**. If risk data is missing for a foreign-issued card, PayGlocal may reject the transaction.
</Warning>

For **RuPay cards**, `ipAddress`, `httpAccept`, and `httpUserAgent` are mandatory.

## Network Token / AltID Support

To use network tokens or alternative IDs instead of raw card data, send a `tokenData` block instead of `cardData`:

```json
"tokenData": {
  "altId": "true",
  "number": "4039073788299302",
  "expiryMonth": "07",
  "expiryYear": "2023",
  "cryptogram": "ASNJBSHA988943NJS",
  "requestorID": "BBFH8838NK",
  "hashOfFirstSix": "fnweiu9432iu43299234",
  "firstSix": "403907",
  "lastFour": "2023",
  "cardBrand": "visa"
}
```

## Industry-Specific Data

For certain industries, additional data blocks are supported (and may be required for fraud protection benefits):

| Industry | Data Block | Details |
|----------|-----------|---------|
| Airlines / OTA | `flightData[]` | Flight booking, leg, and passenger data |
| Hospitality | `lodgingData` | Check-in/out, room, and guest data |
| Ground Transport | `trainData[]`, `busData[]`, `cabData[]` | Journey and passenger data |

See [Risk Data Fields](/api-fields/risk-data-fields) for the complete field reference.
