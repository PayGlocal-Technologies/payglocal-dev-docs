### Top-Level Field Descriptions

| Field | Type | Description |
|-------|------|-------------|
| `gid` | string | PayGlocal global transaction identifier. Unique per API response. Use this when contacting support. |
| `timestamp` | string | Server timestamp of the response in `DD/MM/YYYY HH:MM:SS` format. |
| `reasonCode` | string | Empty string on success. Populated with an error code on failure. |
| `data` | object | The response payload. Contains `merchantInfo` and `merchantOnboardingCheckListStatus`. |

### `merchantInfo` Fields

| Field | Type | Description |
|-------|------|-------------|
| `onboardingId` | string | PayGlocal-generated unique identifier for this onboarding session. |
| `partnerOnboardingId` | string | The `externalOnboardingId` submitted by the partner at creation. |
| `onboardingStatus` | string | Current lifecycle status of the onboarding. See [API Flow Overview](/guides/api-flow-overview#state-transitions). |

### `merchantOnboardingCheckListStatus` Fields

| Field | Possible Values | Description |
|-------|-----------------|-------------|
| `businessDetails` | `COMPLETE`, `INCOMPLETE`, `NOT_APPLICABLE` | Business information submission status |
| `beneficialOwners` | `COMPLETE`, `INCOMPLETE`, `NOT_APPLICABLE` | Beneficial owner submission status |
| `bankDetails` | `COMPLETE`, `INCOMPLETE`, `NOT_APPLICABLE` | Bank details and penny drop status |
| `authorisedSignatory` | `COMPLETE`, `INCOMPLETE`, `NOT_APPLICABLE` | Authorised signatory submission status |
| `vkyc` | `COMPLETE`, `INCOMPLETE`, `NOT_APPLICABLE` | Video KYC completion status |
| `digiLocker` | `COMPLETE`, `INCOMPLETE`, `NOT_APPLICABLE` | DigiLocker verification completion status |
| `tncAcknowledged` | `COMPLETE`, `INCOMPLETE`, `NOT_APPLICABLE` | T&C acknowledgement status |
| `documents` | `COMPLETE`, `INCOMPLETE`, `NOT_APPLICABLE` | Document upload status |
| `products` | `COMPLETE`, `INCOMPLETE`, `NOT_APPLICABLE` | Product and fee configuration status |
| `documentsToBeUploaded` | array of strings | Document types still required (empty when all uploaded) |

## Common Error Response

All error responses follow this structure:

```json
{
  "gid": "gl_9c2645ed09edb22e",
  "timestamp": "10/01/2026 15:00:00",
  "reasonCode": "VALIDATION_ERROR",
  "data": {},
  "errors": {},
  "errorDetails": [
    {
      "field": "externalOnboardingId",
      "message": "Required field is missing"
    },
    {
      "field": "panNumber",
      "message": "Required field is missing"
    }
  ]
}
```

### Error Response Field Descriptions

| Field | Type | Description |
|-------|------|-------------|
| `gid` | string | PayGlocal transaction ID. Provide this to support when reporting issues. |
| `timestamp` | string | Server timestamp of the error response. |
| `reasonCode` | string | Machine-readable error category (e.g., `VALIDATION_ERROR`, `NOT_FOUND`, `FORBIDDEN`). |
| `data` | object | Empty object `{}` on error responses. |
| `errors` | object | High-level error object. May contain additional context. |
| `errorDetails` | array | Array of field-level error objects. Each entry contains `field` (the problematic field name) and `message` (human-readable description of the issue). |

### Using `errorDetails` for Debugging

The `errorDetails` array provides field-level granularity. Iterate over it to surface validation messages to merchants:

```python
for error in response["errorDetails"]:
    print(f"Field '{error['field']}': {error['message']}")
# Field 'externalOnboardingId': Required field is missing
# Field 'panNumber': Required field is missing
```

For the full list of HTTP error codes and common scenarios, see [Response Codes & Errors](/reference/response-codes-and-errors).
