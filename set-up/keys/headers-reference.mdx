<Note>PayGlocal uses two different authentication systems for its two API surfaces. Never mix Onboarding API headers with Payment API headers.</Note>

## Onboarding API Headers

Used with the partner merchant onboarding API endpoints (`/gcc/v2/partner/merchant/onboard/*` and `/gcc/v2/partner/merchant/verification/*`).

| Header | Value | Required | Description |
|---|---|---|---|
| Content-Type | application/json | Yes | All requests |
| x-gl-auth | `<API_KEY>` | Yes | Static API key generated from the PayGlocal Partner Dashboard |
| x-gl-digest | `<HMAC_SHA256_BASE64>` | Yes | HMAC-SHA256 of the raw request body (POST/PUT) or the request URI path (GET), Base64-encoded. Recomputed per request. |

See [Onboarding Authentication](/set-up/partner-onboarding/authentication) for digest computation details and common mistakes.

## Payment API Request Headers

Used with all payment initiation, status, refund, and SI endpoints (PayCollect and PayDirect, `/gl/v1/payments/*`).

| Header | Value | Required | Description |
|---|---|---|---|
| Content-Type | application/json | Yes | All requests |
| x-gl-token-external | `<JWS_TOKEN>` | Yes | RSA-signed JWT of the serialized request body, signed with your private key using RS256. Recomputed per request. |
| x-gl-merchantid | `<MERCHANT_ID>` | Yes | Your Merchant ID from GCC dashboard TID Details |
| x-gl-kid | `<KEY_ID>` | Yes | Key ID extracted from your private key filename — the part before the underscore in `<kid>_<mid>.pem` |
| x-gl-kid-mid | `<CHILD_MID>` | Conditional | Required only for portfolio/parent-child MID configurations. Pass the child merchant's MID here; `x-gl-kid` remains the parent's KID. |

See [Payment API Authentication](/api-reference/payments-v2/common/authentication) for the full JWS signing flow and [Request Construction](/set-up/keys/request-construction) for code samples.

<Warning>For PayDirect flows that include card data, encrypt the card data sub-object with PayGlocal's public certificate (PUBCERT) in JWE format before JWS signing. Sending raw card data without JWE encryption is a PCI DSS violation.</Warning>

## Payment API Response / Callback Header

Sent by PayGlocal on the callback POST to your `merchantCallbackURL`.

| Header | Value | Description |
|---|---|---|
| x-gl-token | RS256-signed JWT | Contains the payment result payload. Verify the RS256 signature using PayGlocal's PUBCERT before reading the status. |

The token payload contains `status`, `gid`, `merchantUniqueId`, and `iat`. If signature verification fails, do not trust the callback — query the payment status via [Get Transaction Status](/api-reference/payments-v2/common/get-transaction-status) using the `gid` from your original GPI response.

See [Downloading the Public Certificate](/set-up/keys/public-certificate) and [Verifying Callback Signatures](/set-up/keys/verifying-signatures).

## MCA API Headers

Used with Merchant Collection Account endpoints (`GET` account fetch, `POST` document upload presigned URL).

| Header | Value | Required | Description |
|---|---|---|---|
| Content-Type | application/json | Yes | All requests |
| x-api-key | `<API_KEY>` | Yes | API key provisioned by your account manager for MCA access. No request signing required. |

See [MCA API Reference](/api-reference/mca/overview) for endpoint details.

## Quick Reference: Which Headers for Which API?

| API Surface | Auth Headers |
|---|---|
| Partner onboarding (create-onboarding, upload-documents, verification, etc.) | `x-gl-auth` + `x-gl-digest` |
| Payment initiation, status, refund, SI (PayCollect + PayDirect) | `x-gl-token-external` + `x-gl-merchantid` + `x-gl-kid` |
| Portfolio/parent-child multi-MID payments | Above three + `x-gl-kid-mid` |
| MCA (account-fetch, document-upload) | `x-api-key` |
| Callback receipt (inbound from PayGlocal) | `x-gl-token` (verify signature — do not send) |
